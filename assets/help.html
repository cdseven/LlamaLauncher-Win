Llama Launcher Help

Model Selection

Choose a .gguf model file from your configured models directory. Models are listed with their estimated parameter count and file size.

The parameter count is extracted from the filename (e.g. 7B, 70B).

Context Window

Context as in "Maximum Chat Length." The context window determines how many tokens the model can process at once. Larger contexts use more VRAM.

Enable "More context sizes" to access extended options from 4K up to 2M tokens. Be cautious with very large values as they require significant memory.

More Context Sizes

Expands the context window options to include additional options ranging from 4K to up to 2M tokens.

Larger conext window sizes require more memory. Slow inference or out-of-memory errors may result if excessively large values are used here.

Disable Thinking / CoT

Some models have a reasoning or "think" mode where the model talks to itself before generating the final response. Small models can produce poor output as a result of this. Even larger models can be wasteful when the <think> block is enabled. These two options are ways of skipping it.

By Chat Template tells the model to skip the thinking phase using its own prompt template. This is the preferred method and is sufficient when using llama-server. Adds --chat-template-kwargs '{"enable_thinking":false}' to the command.

By Forced Override suppresses thinking regardless of the template. When using llama-cli this option may be needed for full suppression of the <think> block. Adds --reasoning-budget 0 --reasoning-format none to the command.

Leave both unchecked if you want to observe the model's reasoning process.

Jinja Templating

Jinja is always enabled (--jinja). This allows llama-server to use the chat template embedded in the GGUF file for proper message formatting.

Flash Attention

Flash attention is always enabled (--flash-attn auto). It accelerates inference and reduces VRAM usage on supported GPUs.

Stop on Exit

When checked, closing Llama Launcher will automatically kill any running llama-server.exe process.

Uncheck this if you want the server to keep running after the launcher is closed.

Models Path

The directory where your .gguf model files are stored.

Use Browse to change the path, or Reset to restore the default (./models). The path is saved in ini.ini.

Bin Path

The directory containing llama-server.exe.

Use Browse to change the path, or Reset to restore the default (./bin). The path is saved in ini.ini.

Backend Selection

Choose between llama-server and llama-cli backends:

  • llama-server: Runs a local API server that can be connected to by other applications or web interfaces
  • llama-cli: Runs an interactive chat in a separate terminal window

The server backend is typically used for applications that need to interface with models via API calls, while the CLI backend provides a direct chat interface in a separate terminal window.

Port Shift

When checked, llama-server will listen on port 8081 instead of the default 8080. Adds --port 8081 to the command.

Maybe useful when running a local OpenWebUI instance, which may be using port 8080 by default.

Custom Arguments

Enter any additional command line arguments you want to pass to the llama executable. These are appended to the end of the generated command.

For example: --threads 8, --temp 0.7, --gpu-layers 99

Be careful with this field — invalid or conflicting arguments may cause the launch to fail. Refer to the llama.cpp documentation for available options.
